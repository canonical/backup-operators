# backup-integrator Terraform module

This folder contains a base [Terraform][Terraform] module for the `backup-integrator` charm.

The module uses the [Terraform Juju provider][Terraform Juju provider] to model the charm
deployment onto any machine environment managed by [Juju][Juju]. `backup-integrator` is a
subordinate charm, so this module does not expose a `units` variable.

## Module structure

- **main.tf** - Defines the Juju application to be deployed.
- **variables.tf** - Allows customization of the deployment. Also models the charm configuration,
  except for exposing the deployment options (Juju model UUID, channel or application name).
- **outputs.tf** - Integrates the module with other Terraform modules, primarily
  by defining potential integration endpoints (charm integrations), but also by exposing
  the deployed Juju application.
- **terraform.tf** - Defines the Terraform and Juju provider versions.

## Using backup-integrator base module in higher level modules

If you want to use `backup-integrator` base module as part of your Terraform module, import it
like shown below. Always pin the `?ref=` to a released tag or a commit hash: CC008 does not
allow floating references such as branches.

```text
data "juju_model" "my_model" {
  name = "my-model"
}

module "backup-integrator" {
  source = "git::https://github.com/canonical/backup-operators//terraform/charm/backup_integrator?ref=backup-integrator-tf-1.0.0"

  model_uuid = data.juju_model.my_model.uuid
  # (Customize configuration variables here if needed)
}
```

Create integrations, for instance:

```text
resource "juju_integration" "my-app-backup" {
  model_uuid = data.juju_model.my_model.uuid
  application {
    name     = module.backup-integrator.application.name
    endpoint = module.backup-integrator.requires.backup.endpoint
  }
  application {
    name     = "my-app"
    endpoint = "backup"
  }
}
```

The complete list of available integrations can be found [in the Integrations tab][backup-integrator-integrations].
